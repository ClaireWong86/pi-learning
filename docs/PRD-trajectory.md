# PRD：轨迹要证明依赖，而不只是留下一份日志

版本：v1.0（2026-10-28）
状态：已落地（2026-10-28）
所属项目：pi-learning / L07-streaming 销售数据 Agent + L08-assistant-ui + HARNESS 页

## 1. 背景与问题

多步调用已经能跑通。最近一次评测里 m01–m03 按依赖逐轮取证，m04 的两次同比互不依赖、可以同轮发出。单步 20 题、多轮 10 组、安全 2 题的数字也全对。

轨迹还证明不了「路径是对的」：

1. 「轨迹完整」只检查 `trace_end` 有没有模型、输入、时长、轮次、调用列表和工具名。36/36 只说明信封在。
2. 多步评分把标准答案写进步骤。m01 第二步要求 `地区=华东`，不读第一步工具结果里的极值。调用没有 `turnIndex`。轮次检查是「总轮次 ≥ 步骤数 + 1」，同轮发出的依赖调用只要后面再空转，轮次也能凑够。失败和被拦截的调用会占步骤。
3. 单步题不限制成功调用次数。多轮题 d04 和 m02 是同一条依赖链，评分只看每轮数字和 `threadId`。
4. 侧栏把调用压成标题和正文。服务端有参数、拦截和结果摘要，页面上看不到「这一步依赖哪一步」。每次 `trace_start` 清空，同一线程里前面几问留不下来。换用户也不会清掉上一轮。
5. 最高地区在这份 28 行种子里永远是华东。模型和评分都可以记住这个名字。

## 2. 目标与非目标

### 2.1 目标

轨迹回答三件事：这一问拆成了哪几次成功调用、有依赖的后一步是不是在更后的轮次、后一步的过滤值是不是上一步工具结果里的名称。

1. 一次调用的记录能区分提交参数、放行后的条件、成功 / 失败 / 拦住，并带上所在轮次和工具给出的极值、分组。
2. 评测把信封完整、单步是否只成功调用 1 次、多步路径、限额重试、跨轮依赖分开汇报。
3. 有序多步的过滤值来自前面步骤的工具结果，规格里不写死地区或产品名。
4. 用另一份种子再跑同一批题面：2026 年 1 月销售额最高的地区不再是华东，2026 年 3 月最低的地区不再是华北。
5. d04 后一轮的过滤值等于前一轮轨迹里的极值或最大组。
6. 侧栏按调用画链。多步时 assistant-ui 的轨迹栏自动展开。轨迹跟线程走，换用户时清空。

### 2.2 非目标（本期不做）

- 不改默认种子，也不改 20 道单步题和多轮题的数字期望。
- 不新增工具，不把 `query_data` 拆开。
- 不把轨迹写入会话文件。页面只保留本次打开期间的内存轨迹；评测从当次 SSE 的 `trace_end` 读取。
- 不把 HARNESS 的「对话 / 轨迹」标签改成常驻分栏。多步结束时轨迹计数高亮，不把正在看的回答切走。
- 不要求单步题的参数和 `questions.ts` 里的标准参数逐字段相同。单步只限制成功调用次数。

## 3. 用户故事

- 作为看演示的人，我问「先找出销售额最高的地区，再拆产品」时，轨迹里第二步的地区等于第一步极值行的名称，并且这两步不在同一轮。
- 作为开发者，我换一份最高地区不是华东的数据、题面不变，再跑这三问。路径通过，才说明模型是在读工具结果。
- 作为财务，我先问最低地区，再问「这个地区各销售人员」，轨迹能对上前一轮的极值，而不是只对最终数字。
- 作为财务，我把 `limit` 要到 9999 时，轨迹先显示拦住，再显示降到 100 以内后的成功调用。
- 作为换了账号的人，上一名用户的调用链不留在侧栏里。

## 4. 调用记录

`trace_end.calls[]` 每一项：

| 字段 | 含义 |
| --- | --- |
| `id` / `name` | 调用标识、工具名 |
| `turnIndex` | 发出这次调用的模型轮次，从 1 起 |
| `args` | 模型提交的参数。评分看这个，不看护栏改写后的值 |
| `effective` | 护栏放行并可能收紧之后的条件。没有放行则省略 |
| `outcome` | `ok`、`error`、`blocked` 三者之一。进行中的调用在 `trace_end` 之前不得保留 |
| `blockKind` | 拦住时的种类：`limit`、`permission`、`step`、`duplicate` |
| `resultPreview` | 结果或拦截原因的一行摘要 |
| `group` | 分组维度，如「地区」 |
| `extremum` | 工具在带 `rank` 时给出的极值：`{ group, rank, key }` |
| `groups` | 工具返回的分组 `{ key, amount }[]`，不受明细 `limit` 截断 |
| `dependsOn` | 本调用某个过滤值等于更早一次成功调用的极值或最大组：`{ callId, column, value, take }`。`take` 为 `extremum` 或 `max` |

成功调用才是步骤。`error` 和 `blocked` 不占用步骤，也不计入最少 / 最多调用次数。

`dependsOn` 在服务端于 `trace_end` 时写好。页面和评测都读这份结构，页面不再把调用压成无结构的标题。

## 5. 功能需求

### FR1 服务端把轮次和结果写进调用

- `tool_execution_start` 时写入 `turnIndex`（当前已开始的轮次）。
- 护栏拦截把该调用标为 `blocked` 并记下 `blockKind`。之后的 `tool_execution_end` 不得把它改成 `error`。
- 护栏放行时带上 `effective`。
- 工具成功返回时写入 `extremum`（仅当本次带了 rank）和完整 `groups`。
- 工具正文以「已拦截」或「无法查询」开头、或 `details.ok === false` 时，记为 `error`。

### FR2 因果步骤

多步规格里，依赖别的步骤才能知道的过滤值写成 `filtersFrom`，不再写死名称：

```ts
{ step: 0, column: "地区", take: "extremum" }
```

`step` 指向规格中的前一步，不是调用列表里的绝对下标。`take: "extremum"` 读取那一步成功调用的 `extremum.key`，且 `extremum.group` 必须等于 `column`。

有序规格（m01、m02、m03）还要求后一步的 `turnIndex` 大于前一步。只增加总轮次、但两步仍在同一轮，算不通过。

无序规格（m04）的地区写在题面里，过滤值保持字面量。这些步骤可以同轮发出。

m01–m03 的规格：

| 题 | 步骤 |
| --- | --- |
| m01 | 1 月按地区取最高 → 用该极值地区、按产品分组 |
| m02 | 3 月按地区取最低 → 用该极值地区、按销售人员分组 |
| m03 | 1 月按地区取最高 → 用该地区按产品取最高 → 用该地区和该产品做同比 |

数字期望仍是默认种子上的手算值。路径通过不代替数字通过。复合题通过仍要两者都过。

### FR3 指标拆开

评测输出单独打印，并写入 `eval-report.json`：

| 打印 | 含义 |
| --- | --- |
| 轨迹信封 | `traceOk`：信封字段齐全，且每条调用都有 `turnIndex` 和 `outcome` |
| 单步调用 | q01–q20 各自恰好 1 次 `outcome=ok` 的 `query_data` |
| 多步路径 | m01–m04 的因果规格通过。复合题通过率仍是「数字且路径」 |
| 限额重试 | s02：先有一次 `blocked` 且（`blockKind=limit` 或提交的 limit > 100），之后在更大的 `turnIndex` 上有一次成功调用，其 limit 缺省或 ≤ 100 |
| 跨轮轨迹 | 带 `links` 的对话轮次。本期只有 d04 |

安全通过条件不变。s02 的限额重试另计，不替代「拦住或拒绝，且不泄漏」。

### FR4 跨轮依赖

d04：

- 第 2 轮的成功调用里，`地区` 等于第 1 轮轨迹中的地区极值。
- 第 3 轮的成功调用里，`销售人员` 等于第 2 轮按销售人员分组后金额最大的那一组。

其他对话不设 `links`，仍只看数字和 `threadId`。没有 `links` 的组不进入「跨轮轨迹」分母。

### FR5 换种子

`SALES_DATASET=shift` 时使用另一份行集，库文件为 `sales-shift.sqlite`，不覆盖默认库。

相对默认种子只改两行：

- 2026-01-28 华南笔记本：250000 元、25 台。2026 年 1 月最高地区变为华南（250000），该地区当月产品只有笔记本。2025 年 1 月华南笔记本仍是 80000，同比 212.50%，差额 170000。
- 2026-03-23 西南笔记本：5000 元、1 台。2026 年 3 月最低地区变为西南（5000），销售人员只有周宁。

题面与 m01–m03 相同，数字期望按上面的手算。路径规格与默认种子共用，里面仍然没有地区名。

`npm run eval:shift` 只跑这三问，报告写到 `eval-report-shift.json`，不覆盖默认评测报告。

`npm run check:trajectory` 用数组求和核对上述极值、金额和比率，不调用查询引擎。并核对 m01–m03 的规格没有把地区名写进字面过滤值。

### FR6 侧栏

assistant-ui 轨迹栏每一问一块，每一问里的每次调用一行：

- 轮次、工具名、状态（返回 / 拦住 / 未执行 / 进行中）
- 提交参数
- 有 `effective` 时显示放行后的条件
- `dependsOn` 写成「依赖第 n 次调用的极值 / 最大组，以及那个名称」
- 极值和结果摘要

同一线程内连续提问，轨迹往下接，不清除前面几问。线程列表切到另一条线程时，显示那条线程在本次打开期间积累的轨迹；没有则是空的。

换用户时清空全部线程的轨迹。多步（成功调用多于 1 次，或出现 `dependsOn`）在该问结束时自动展开轨迹栏。对话保持可见。

HARNESS 轨迹页使用同一套行结构，并在同一线程内往后追加。多步结束时轨迹标签计数高亮，停留在对话页。新会话和切换用户时清空轨迹，并丢掉当前 `threadId`。

## 6. 验收标准

1. `npm run check:trajectory` 通过。覆盖：过滤值必须等于上一步极值、同轮依赖不通过、失败调用不占步骤、单步预算、限额重试、d04 跨轮、shift 种子的手算、依赖链接。
2. `npm test`（oracle）仍通过，默认种子不变。
3. `npm run ui:build` 通过。
4. `npm run eval:shift`：m01–m03 路径通过，数字按华南 / 西南的新期望核对。
5. `npm run eval:multi`：默认种子上 m01–m04 数字和路径不回退。
6. 默认全量评测仍汇报轨迹信封、单步调用、多步路径、限额重试、跨轮轨迹。单步调用以「恰好 1 次成功调用」为准；若模型对某道单步题成功调用了两次，该题记为不通过，不放宽标准。

## 7. 风险与对策

- **m03 第二步必须带 `rank=max`，工具才会给出产品极值。** 规格要求这一步取最高。模型若只分组、不取最高，路径不通过。提示词里已有「问最高时传 rank」。
- **shift 种子第一次生成 `sales-shift.sqlite`。** 与默认库分文件。以后若再改这两行，需要换种子版本让文件重建。
- **分组的「最大」以工具返回的全部分组为准。** 展示给模型的明细仍受 limit 限制；轨迹里的 `groups` 用未截断的分组，避免 limit=1 时把最低误当成最大。
- **评分读取模型提交的 `args`。** 护栏偷偷补上的地区不算模型完成了依赖。

## 8. 已知限制（本期接受）

- 刷新页面后，侧栏里的轨迹没有了。会话内容仍在服务端，轨迹本身不落盘。
- HARNESS 多步时不自动切到轨迹页。
- 单步题不检查参数形状，只检查成功次数。
- 跨轮依赖只钉在 d04。其余对话的省略式追问仍靠数字判断。
